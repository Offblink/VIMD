# VIMD

**VIM + MD** — 在终端里编辑 Markdown，基于 [Textual](https://textual.textualize.io/)。

## 安装与运行

```bash
pip install -r requirements.txt
python vimd.py 文档.md
```

发布版双击 `VIMD.exe`（把 `.md` 拖到它上面也行）。`VIMD.exe` 是**启动器**：它只判单例、唤醒已有窗口，真正在跑的编辑器是同目录的 `VIMD-tui.exe`。

## 功能

- 三视图：编辑 `Alt+1` / 预览 `Alt+2` / 分屏 `Alt+3`，首次启动默认分屏，选择会被记住
- **单例（按文件）**：同一个文件重复打开不会再开一个窗口 —— 直接把已经在编辑它的那个窗口抬到前台；不同文件仍各开各的窗口（想并排对着看两个文件照旧）。源码运行 `python vimd.py` 一样有单例
- 预览增量重绘：打字时只重建改动的那几个块，停顿不再整篇重算（实测末尾输入 8-25ms，全量要 280-940ms）
- 分屏预览自动跟随光标：光标在预览里的位置贴住预览底边，上面留得住刚写过的上文；手动滚开预览即停跟（方便对着上文写下文），滚回底部（`End`）恢复
- 编辑区自动换行：文字到边即折行，没有横向滚动；行号按显示行递增
- 格式快捷键作用于选中内容，再按一次取消：加粗、斜体、代码块、链接、内嵌图片
- 打开和另存为使用系统文件对话框；对话框不可用时回退为内置路径输入
- 查找替换弹窗（右下角）：区分大小写勾选、替换当前、全部替换；关窗后 `Alt+X` 继续往下找、`Alt+Z` 往回找
- 底栏「设置」里可切换显示行号
- 预览中的链接和图片用系统默认程序打开
- 文件打开期间不可被外部移动、删除或改名；支持 UTF-8、GBK 等多种编码
- 顶栏显示文件名与标题，底栏左侧是键位、右侧行列号；选中文段时在模式左边显示选中字数（含标点与空格，折行不算）
- 退出或新建前对未保存的修改进行确认

## 快捷键

| 分类 | 按键 |
|---|---|
| 文件 | `Ctrl+N` 新建 · `Ctrl+O` 打开 · `Ctrl+S` 保存 · `Ctrl+Shift+S` 另存为 |
| 视图 | `Alt+1` 编辑 · `Alt+2` 预览 · `Alt+3` 分屏 |
| 格式 | `Ctrl+B` 加粗 · `Ctrl+I` 斜体 · `Ctrl+K` 代码块 · `Ctrl+L` 链接 · `Ctrl+Shift+L` 图片 |
| 查找 | `Ctrl+F` 打开弹窗 · `Alt+X` 下一个 · `Alt+Z` 上一个 · 弹窗内 `Enter` 也是下一个 |
| 编辑 | `Ctrl+A` 全选 · `Ctrl+Z` 撤销 · `Ctrl+Y` 重做 |
| 其他 | `Alt+H` 帮助 · `Alt+L` 显示行号 · `Alt+Q` 退出 |

## 保存机制

- **保存**（`Ctrl+S`）与**另存为**（`Ctrl+Shift+S`）优先弹出系统文件对话框；对话框不可用时回退为内置路径输入，两条路都会真正写入磁盘。另存为未写扩展名时自动补 `.md`
- **打开期间锁文件**：正在编辑的文件会被锁定，外部程序无法移动、删除或改名；关闭或切换到别的文件时自动解锁
- **自动恢复日志**：每次编辑停顿半秒后，如果内容和上次保存不一致，草稿就写进 `%APPDATA%\VIMD\recovery.json`；**按文件分开存**——每个文件各自一条，保存或改回一致时只清自己那条。因此强杀、断电、崩溃都杀不死未保存的修改
- **异常退出后恢复**：带着未保存内容异常退出的程序，下次**打开那个文件**时会弹出该文件自己的恢复框，可选 恢复 / 丢弃 / 稍后；选了"稍后"，底栏会保留"恢复"按钮，随时可以重新打开恢复框。打开别的文件不会误弹、更不会把 A 的草稿覆盖进 B
- **文件被外部改过时不误报**：草稿写下之后文件又被别的程序（例如 agent）改过，打开时可以看出来——不弹恢复框，恢复草稿直接同步成文件当前内容。这种差异不是未保存丢失，所以不以 recovery 为准
- **退出与新建前确认**：有未保存修改时先询问。选了保存会**先真正写盘完成**，再继续退出或新建；未命名文件先转到另存为，落盘后接着走

## 说明

- **单例的口径**：判定键是归一化后的绝对路径（大小写、`\` 与 `/`、`..` 都算同一个文件）。**未命名**文档（不带参数启动）自成一类：连着双击两次快捷方式只会得到第一个窗口。被单例挡下的那次启动**不会**弹任何窗口 —— 这是 `VIMD.exe` 做成窗口化启动器的原因（控制台 exe 的窗口由系统在建进程时就建好了，判重必然先闪一下）
- 如果 VIMD 是跑在**已有终端窗口**里的一个标签（不是它自己独占的那个窗口），唤醒时会把那个终端窗口抬到前台，但**不会替你切标签** —— 切标签归终端自己管
- 在 Windows 上用**终端**（如 Windows Terminal）运行，别用控制台主机：实测大量 CLI（包括 VIMD）在控制台主机里图标和显示都不正常
- 斜体用 `Ctrl+I`：需要终端支持 kitty 键盘协议（Windows Terminal 支持）；不支持的终端改用 `Alt+I`
- 缩放（编辑区+预览一起变大）用终端自己的 `Ctrl+=` / `Ctrl+-` / `Ctrl+0`；VIMD 不接管这几个键，字体大小归终端管
- 中文由终端输入法处理，组词完成后整词上屏
- 编辑区语法高亮需要安装 tree-sitter 的 Markdown 语法包，未安装时为纯文本，不影响预览渲染
- 文件锁定与编码探测逻辑取自 [MDPad](https://github.com/Offblink/MDPad)
